# Stekkies Together

A small, offline-capable classroom proof of concept: find roommates for a home, then compare individual search with group-enabled housing access in a fictional Rotterdam market.

## Open the demo

Double-click **index.html** in this folder. No installation, account, internet connection or server is required. Keep the accompanying files together. If using the ZIP, extract it first.

## A three-minute presentation

1. Follow Alex through the tenant journey: open the €2,250 home, find roommates and review the €750 share and household requirements.
2. Open **Market simulation**. Leave the population at 150 and select **Start**.
3. Watch seekers enter over 12 rounds. Both markets receive the same arrivals; homes change colour when an individual or group is assigned. The Alex tracker connects this market view to the tenant story.
4. **Pause** or use **Next** to explain one step. The round activity lists real matches calculated that round. Drag the round slider forward or backward to jump to any point, including the final round. Moving the slider pauses playback and recalculates that point in the timeline.
5. At completion, compare the outcome. Try 50 or 300 seekers to vary the size of the roommate pool while keeping the same 100 homes.

Automatic playback takes about 30 seconds. Reset starts a fresh market; switching to the tenant view pauses playback. Results are repeatable from the same data. The round count is not calibrated to real days.

## Keep changes small

There are no third-party libraries, build tools, API calls, database, authentication or generated bundles.

| File | Responsibility |
|---|---|
| `data.js` | Fixed-seed fictional profiles, listing inventory, curated demo trio and settings |
| `matching.js` | Eligibility, mutual suitability, group selection and allocation |
| `simulation.js` | Stateful arrival rounds, persistent allocations and outcome summaries |
| `simulation-view.js` | Playback, round slider and market visualization |
| `simulation.css` | Compact simulation layout and animation |
| `theme.css` | Shared Stekkies branding, local fonts and application layout |
| `app.js` | Tenant journey and top-level view switching |
| `index.html` | Page structure and local apartment photo |
| `styles.css` | Stekkies-inspired visual design and responsive layout |
| `tests.cjs` | Meaningful matching and simulation checks, using Node’s built-in assertions |
| `TESTING-AND-LEARNING.md` | Evidence, assumptions and observed learning |

The three demo profiles are fixed explicitly. The remaining fictional profiles and listings are generated once from a fixed seed when the page loads, giving an unchanging dataset without hundreds of manually maintained records. Preferences are not generated by an AI model or changed during the demo.

Change budgets, profile requirements, rents and settings in `data.js`. Change the matching policy in `matching.js`. Refresh the browser after edits. Primary profile and home facts read from the fixtures; longer narrative copy is intentionally written for the agreed three-person Rotterdam journey and should be reviewed if that story changes.

The UI’s initial HTML also supplies readable example content before JavaScript loads. The matcher and simulation can run independently of the UI. With Node installed, run `node tests.cjs` from this folder.

## Model boundaries

- 100 fictional homes: 20 single-bedroom homes and 80 multi-bedroom homes, some unsuitable for sharing.
- Selected populations of 50, 150 or 300 enter over 12 rounds. Larger populations retain the smaller population’s profiles but bring more people in per round.
- Both counterfactual markets start with the same inventory and receive identical arrivals. Their allocations evolve independently. Homes and people already assigned are never assigned again.
- Both markets check solo rentals and allow occasional informal grouping. Each round has a 25% seeded chance of one informal group-search opportunity, subject to the same eligibility and mutual preferences. Together additionally searches systematically for groups. This opportunity rate is a configurable teaching assumption, not an empirical success rate.
- Hard checks: budget, district, moving month, occupancy, student/sharing permission, income or allowed guarantor support, and every tenant’s own dealbreaker.
- Other lifestyle preferences rank compatible candidates. Each pair must match on at least 3 of the 4 attributes at the default threshold.
- Groups split rent equally and fill 2–4-bedroom homes. Income and guarantor rules are fictional teaching assumptions.
- Allocation is greedy and sensitive to arrival order. Early reservations affect later possibilities; globally optimal allocation is not claimed.
- Mutual acceptance is assumed. No actual applications, leases, withdrawals or new listings occur. The animation is presentation pacing, not simulated real-world elapsed time.
- No live AI service is used. The rules run in the browser at each step. Fixed data makes replay deterministic; repeating a run is not additional independent evidence.

## Brand assets

The academic demo uses the [official Stekkies wordmark](https://www.stekkies.com/static/roomraider/img/logo-text-red.svg), [Poppins Bold](https://www.stekkies.com/cf-fonts/s/poppins/5.2.7/latin/700/normal.woff2) and [Inter variable](https://www.stekkies.com/cf-fonts/v/inter/5.2.8/latin/wght/normal.woff2) served by the [official site](https://www.stekkies.com/en/), saved locally for offline use. The logo remains a Stekkies brand asset. Font families are open-source: [Poppins](https://github.com/itfoundry/Poppins) and [Inter](https://github.com/rsms/inter).

Simulation colours: blue = direct rental or self-organized group, green = platform-matched group, pale grey = unassigned. The large number inside each home is its bedroom count. The slider supports mouse/touch dragging and keyboard arrows, Home and End. Home inspection was removed to keep the tool focused.
